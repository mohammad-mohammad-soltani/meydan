# Feed V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a configurable, explainable Feed V2 behind an immediately reversible feature flag without changing the public `/timeline` contract.

**Architecture:** Keep `TimelineController` and `TimelineSession` as the public orchestration and pagination boundary. Add a pure Feed domain pipeline for settings, candidate merging, hydration, filtering, scoring, sorting and diversity; adapt it through a V2-only branch selected before V1 construction. Add administrator-only REST settings/preview endpoints and an authenticated Next.js management page that consumes them through the existing proxy.

**Tech Stack:** PHP 8.1 WordPress plugin, `WP_Query`/`$wpdb`, WordPress object cache/options, Next.js 16 App Router, TypeScript/React, Node test runner, PHP CLI contract tests.

**Spec:** `docs/superpowers/specs/2026-09-20-feed-v2-design.md`

## Global Constraints

- Preserve `GET /timeline`, its envelope and TimelineSession cursor semantics; normal callers never receive ranking metadata.
- `feed_algorithm_v2_enabled=false` must route immediately to unmodified V1, without a migration or V2 side effect.
- Do not add affinity, interaction-graph, semantic, embedding, topic, interest-vector, ML or transformer signals to V2.
- Use only the documented Meydan model sources; role resolution is user actor → user roles and square actor → actual square-owner roles.
- Limit source queries to `max_post_age_hours`; never use random ordering in V2.
- Preview and authorised debug output must be read-only: no views, served-history rows, events, analytics or real-user cache writes.
- Only `administrator` may access Feed settings, preview or debug breakdowns.
- Backend validation is authoritative; frontend validation mirrors it for usability. Save and reset both validate, invalidate cache and audit before/after values.
- Use test-first development: create and run each failing test before the corresponding production code.

## Review Focus

- A zero-engagement post must not become unrankable or cause NaN/Infinity after valid zero-valued settings; Task 3 tests finite zero handling.
- A bucket boundary such as exactly 6, 12, 24, 48 or 72 hours must select exactly one configured bucket; Task 3 tests half-open intervals and inclusive final cap.
- A manually corrupted option document must fall back safely rather than silently enable V2 with unsafe values; Task 2 tests normalization of invalid persisted input.
- A non-administrator must not obtain debug data merely by adding `debug_feed=1`; Task 6 tests both permission and normal-response non-leakage.
- A preview must not update a shared cache key containing a real viewer's served result; Task 5 tests the read-only option and Task 6 tests the controller call path.

$raw = log(1 + $likes) * $s['like_weight']
